# TeXAstra 0.0.28

The extension now uses the TeXAstra name throughout its interface, commands,
settings, runtime filenames, cache directories, and package metadata. The local
extension identity is `texastra.texastra`, and the installer is
`artifacts/texastra-0.0.28.vsix`.

The document command is `texastra.openDocument` (**TeXAstra: Open Document**).
The environment command is `texastra.showEnvironment`. Settings use the
`texastra.*` namespace. Explicit settings under that namespace take precedence;
the configuration adapter still reads previously saved settings so existing
main-file, project-root, distribution, and runtime choices continue working.
Ignored compiler-selection settings no longer appear in the extension settings.

The header, status messages, errors, and README use document terminology and omit
the old product's name and provisional release labels. The badge has been removed.
The Python reference package and Lua compiler assets moved from `prototype/` to
`texastra/`, with corresponding launcher, build, and test paths updated. Source
comments describing experiments were replaced with descriptions of their purpose.
Implementation comments, supported-platform constraints, and third-party notices
remain. Historical research and dated validation records remain in the repository
as evidence and are excluded from the installed extension.

The Linux C++ backend was rebuilt. The existing LuaHBTeX executable was copied to
the renamed runtime path without altering its bytes; its source and patch are
unchanged. Native Windows build recipes also use the new names, but that separate
runtime was not rebuilt or exercised for this release. Internal compiler ABI names
and protocol fields remain compatible.

## Validation

- `node scripts/check_configuration.js`: 15 checks covering defaults, previous
  settings at each scope, and explicit new-setting precedence.
- `node scripts/check_extension_live.js`: 37 extension checks with mocked VS Code
  APIs, including command activation, unsaved buffers, and source synchronization.
- Save, frame-delivery, and project-resolution checks passed.
- `python scripts/check_viewer_latency.py`: 27 Chromium checks, including error
  header behavior, frame delivery, and source-view geometry assumptions.
- `python scripts/check_preamble_stream.py --output texastra-compilation.json`:
  54 checks with the real WSL compiler. Incremental rendering, selection, and
  mappings matched complete builds; invalid input was rejected and recovered.
- `python scripts/check_forward_sync_live.py`: 14 real-browser/WSL checks,
  including navigation to previously unloaded pages and included-source edits.
- JavaScript syntax, Python compilation, and `git diff --check` passed.
- VSIX archive bytes were checked against staging; all 121 installed extension
  files were subsequently checked against the VSIX, allowing VS Code's added
  installation metadata in the manifest. No old product filenames,
  historical documents, or retired asset directory are packaged.
- The installed launcher's environment check, initial compilation, source maps,
  and unsaved-edit rendering passed. The source file remained unchanged.
- The renamed extension was installed and the previous extension registration
  removed. VS Code must reload to activate the new command set.

The complete interactive VS Code Extension Host was not exercised. Reports:
[rename](../results/texastra-rename.json),
[compilation](../results/texastra-compilation.json),
[installed runtime](../results/texastra-installed.json), and
[package](../results/package-0.0.28.json).
